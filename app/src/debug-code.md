## Bug 1: splitEvenly некоректно працює з від'ємним totalCents
Рядок: 58
Симптом: splitEvenly(-1000, 3) повертає [-333, -333, -333] (сума = -999, а не -1000)
Root cause: Math.floor(-1000/3) = -334, remainder = -1000 - (-334*3) = 2.
Цикл додає +1 до перших двох елементів → [-333, -333, -334].
Сума = -1000, але розподіл нерівномірний у неочевидний бік.
Для додатних: перші елементи більші. Для від'ємних: останні — більші за модулем.
Це не критичний баг (сума коректна), але поведінка може здивувати.
Fix:
```ts
// Якщо потрібна симетрія — використати Math.trunc замість Math.floor:
const base = Math.trunc(totalCents / n);
// Але це змінить поведінку для додатних — тому краще залишити як є
// та задокументувати поведінку для від'ємних.
```

## Bug 2: parseAmount приймає "-0" і повертає 0 (втрата знаку)
Рядок: 40
Симптом: parseAmount("-0") повертає 0, а не -0
Root cause: cents = 0*100 + 0 = 0, потім sign === "-" ? -0 : 0.
Фактично -0 === 0 у JS, тому formatCents(parseAmount("-0")) = "0.00", а не "-0.00".
Це edge case — roundtrip "-0.00" → parse → format втрачає мінус.
Fix:
```ts
// Мінімальний fix — відхилити "-0" як невалідний вхід:
const match = /^(-?)([1-9]\d*|0)(?:\.(\d{1,2}))?$/.exec(trimmed);
// Або просто прийняти як by-design: -0 === 0 у JavaScript.
```

Інших багів не виявлено.
