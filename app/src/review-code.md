## Результати рев'ю: `app/src/money.test.ts`

```
[MEDIUM] рядок 25-29: Дублювання з тестом на рядку 10
Проблема: formatCents(5) вже неявно покрито в "positive fractional amounts" (рядок 16 — 50 центів),
а formatCents(1) тестує те саме, що "formats zero as '0.00'" перевіряє для padStart-гілки.
Тест "pads single-digit fractional" частково перетинається з попередніми кейсами.
Рекомендація: Об'єднати або прибрати дублі — залишити один тест на padStart із значеннями 1, 9, 101.
```

```
[MEDIUM] рядок 82-97: splitEvenly не покриває граничні вхідні дані
Проблема: Немає тестів для n=0 (ділення на нуль), від'ємного totalCents,
або великого n > totalCents (де base=0). Ці випадки не валідуються у коді,
тому тести мають документувати фактичну поведінку.
Рекомендація: Додати кейси: splitEvenly(100, 0), splitEvenly(-300, 2), splitEvenly(1, 5).
```

```
[MEDIUM] рядок 99-123: applyDiscount не покриває граничний percent > 100
Проблема: Функція не валідує діапазон percent. Виклик applyDiscount(1000, 150) поверне -500.
Тести не документують цю поведінку — чи це баг, чи by design.
Рекомендація: Додати тест на percent > 100 та percent < 0, щоб зафіксувати фактичну поведінку.
```

```
[LOW] рядок 62: toThrow() без перевірки повідомлення
Проблема: Усі throw-тести перевіряють лише факт викидання, а не текст помилки.
Якщо хтось змінить повідомлення або тип помилки — тести не зловлять регресію.
Рекомендація: Використати toThrow(/Not a valid amount/) для прив'язки до конкретного повідомлення.
```

```
[LOW] рядок 113: Назва тесту "rounds to nearest cent via Math.round" зайво деталізує реалізацію
Проблема: Тест-назва прив'язана до деталі реалізації (Math.round).
Якщо реалізацію змінять на банківське округлення — назва стане невірною.
Рекомендація: Перейменувати на "rounds fractional cents to nearest integer".
```
