# Чек-ліст санітизації даних для AI (команда: payments / fintech)

Багаторазовий чек-ліст перед вставкою тексту в публічну або корпоративну LLM.

## 1. Класифікуй (світлофор)

- [ ] **🔴 Ніколи публічним:** API keys (`X-API-Key`, `sk-live-…`), паролі, connection strings (`postgres://user:pass@host`), PII (ПІБ, email, телефон, ДН, паспорт, ІПН), банківська таємниця (PAN, CVV, IBAN, баланс), production-дампи.
- [ ] **🟡 Лише enterprise/no-train:** внутрішні назви сервісів, гілки, бізнес-логіка (`FeeCalculator.applyTransferFee`), анонімізовані логи з контекстом.
- [ ] **🟢 Можна:** загальний опис бага, acceptance criteria без даних, синтетичні приклади.
- [ ] Сумнів → вважати 🔴.

## 2. Очисти (техніка)

| Техніка | Коли | Приклад |
|---------|------|---------|
| **Redaction** | поле не потрібне для задачі | `CVV → [REDACTED]` |
| **Masking** | потрібна структура | `4111…1234 → ****-1234`, `IBAN → <IBAN>` |
| **Synthetic** | потрібен «реалістичний» приклад | `Олена Шевченко → [CUSTOMER_1]` |
| **Out-of-band** | секрети | ключ у Vault/env; у документі лише `<SECRET_OUT_OF_BAND>` |

## 3. Перевір перед відправкою

- [ ] Чи можна реідентифікувати людину з решти полів?
- [ ] Чи збережена **задача** після санітизації?
- [ ] Чи відповідає tier категорії даних?

## 4. Інструмент під категорію

| Категорія | Інструмент / tier | Нотатки |
|---|---|---|
| 🟢 | Cursor / Copilot (стандарт) | загальні питання, OSS-код |
| 🟡 | **Cursor Business / Claude for Work (no-train)** | внутрішня логіка, тікети з контекстом — обрано через no-train і data residency |
| 🔴 | Не давати моделям | лише локально після redaction/masking |
