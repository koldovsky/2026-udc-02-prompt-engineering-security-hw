# Чек-ліст санітизації даних для AI (команда: payments-core / WS2)

> Багаторазовий документ для підготовки тікетів, логів і коду до передачі в AI-інструменти.
> Застосовано на прикладі JIRA-4821 (Task B).

## 1. Класифікуй (світлофор)

- [ ] **🔴 Ніколи публічним:** секрети (ключі, токени, паролі, connection strings),
      PII (ім'я, email, телефон, ДН, паспорт, ІПН), банківська таємниця
      (картка, CVV, IBAN, рахунок, баланс), production-дані/дампи,
      медичні/держ./регульовані дані.
- [ ] **🟡 Лише enterprise/no-train:** внутрішній код під NDA, бізнес-логіка,
      схеми БД, архітектура, тікети з контекстом, анонімізовані логи.
- [ ] **🟢 Можна публічним:** публічний/OSS-код, синтетика, загальні питання,
      документація без даних, стек-трейс без значень.
- [ ] Сумнів → вважати 🔴.

## 2. Очисти (техніка під категорію)

- [ ] **Redaction** — прибрати повністю (`[REDACTED]`): те, що не потрібне задачі.
      _Приклад: ПІБ, email, телефон, ДН, паспорт, ІПН, баланс._
- [ ] **Masking** — зберегти формат, прибрати значення (`****-1234`, `<IBAN>`):
      коли моделі потрібна структура.
      _Приклад: номер картки → `****-1234`; IBAN → `<IBAN>`; txn → `TX-*****`._
- [ ] **Synthetic** — підмінити реалістичним вигаданим: коли потрібні «справжні
      на вигляд» дані для відтворення.
      _Приклад: замінити реальний account ID синтетичним `ACCT-DEMO-001`._
- [ ] **Секрети — out-of-band:** не маскувати, а **не давати взагалі**
      (env / secret store); якщо «світилися» — ротувати негайно.
      _Приклад: `X-API-Key` → `<SECRET_OUT_OF_BAND>`; DB password → не давати._

## 3. Перевір перед відправкою

- [ ] Чи можна реідентифікувати людину з решти полів? (ім'я+ДН+місто+посада)
- [ ] Чи не несе чутливе вставлений URL / скріншот / лог?
- [ ] Чи збережена **задача** після санітизації?
- [ ] Чи відповідає інструмент/tier категорії даних? (no-train для 🟡)
- [ ] Reporter / assignee email видалено або замінено плейсхолдером?
- [ ] У лог-рядках немає реальних txn ID, IP-адрес, паролів у URL?

## 4. Інструмент під категорію

| Категорія | Дозволений інструмент / tier | Нотатки |
|---|---|---|
| 🟢 | Будь-який публічний AI (ChatGPT, Claude.ai, Copilot free) | Немає PII/секретів — обмежень немає |
| 🟡 | GitHub Copilot Business / Enterprise, Claude for Work (no-train), Azure OpenAI (своя підписка) | Контент не потрапляє в навчання; data residency в межах EU/US |
| 🔴 | **Не давати AI взагалі.** Локальна обробка, ручна редакція або скрипт у захищеному середовищі | Після санітизації → можна передати в 🟡-tier |

### Чому 🟡 вимагає no-train / enterprise tier?

Внутрішня бізнес-логіка (назви методів, гілок, компонентів, схема БД) під NDA може
розкрити архітектурні рішення конкурентам або у витоці. Публічні безкоштовні моделі
можуть використовувати ці дані для дотренування. Enterprise/no-train tier гарантує:

- дані **не потрапляють** у глобальне навчання моделі;
- **data residency** — обробка в погодженому регіоні (EU/US);
- **audit log** — можна довести регулятору (GDPR, PSD2), що дані не витекли.
