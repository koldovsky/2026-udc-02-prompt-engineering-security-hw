# Чек-ліст санітизації даних для AI (команда: payments-core)

> Багаторазовий документ для щоденної роботи з LLM. Перед кожним промптом —
> пройти світлофор, застосувати техніку, перевірити результат.

## 1. Класифікуй (світлофор)

- [ ] **🔴 Ніколи публічним:** секрети (ключі, токени, паролі, connection strings),
      PII (ім'я, email, телефон, ДН, паспорт, ІПН), банківська таємниця
      (картка, CVV, IBAN, рахунок, баланс), production-дані/дампи,
      медичні/держ./регульовані дані.
- [ ] **🟡 Лише enterprise/no-train:** внутрішній код під NDA, бізнес-логіка,
      схеми БД, архітектура, тікети з контекстом, анонімізовані логи.
- [ ] **🟢 Можна публічним:** публічний/OSS-код, синтетика, загальні питання,
      документація без даних, стек-трейс без значень.
- [ ] Сумнів → вважати 🔴.

## 2. Очисти (техніка під категорію)

| Техніка | Коли | Приклад |
|---------|------|---------|
| **Redaction** — прибрати повністю (`[REDACTED]`) | Поле не потрібне для задачі | ДН, баланс, паспорт, CVV |
| **Masking** — зберегти формат, прибрати значення | Моделі потрібна структура даних | `****-1234`, `+380 ** *** ** **` |
| **Pseudonymization** — замінити токеном | Потрібна кореляція між записами | `[CUSTOMER_1]`, `[EMPLOYEE_1]` |
| **Synthetic** — підмінити реалістичним вигаданим | Потрібні «справжні на вигляд» дані для відтворення | `Jane Doe`, `jane@example.test` |
| **Out-of-band** — не давати взагалі | Секрети, ключі, паролі | `<SECRET_OUT_OF_BAND>` + env/vault |

### Правила для секретів

- [ ] Секрети **ніколи** не маскуються — тільки out-of-band.
- [ ] Якщо секрет потрапив у контекст — вважати скомпрометованим, ротувати.
- [ ] Connection strings, API keys, tokens — завжди `<SECRET_OUT_OF_BAND>`.

## 3. Перевір перед відправкою

- [ ] Чи можна реідентифікувати людину з решти полів? (ім'я+ДН+місто+посада)
- [ ] Чи не несе чутливе вставлений URL / скріншот / лог?
- [ ] Чи збережена **задача** після санітизації? (модель усе ще може зрозуміти баг)
- [ ] Чи відповідає інструмент/tier категорії даних? (no-train для 🟡)
- [ ] Чи немає IP-адрес, hostnames, внутрішніх URL у логах?

## 4. Інструмент під категорію

| Категорія | Дозволений інструмент / tier | Нотатки |
|---|---|---|
| 🟢 | Будь-який LLM (ChatGPT, Claude, Copilot, публічні API) | Вільно, без обмежень |
| 🟡 | Enterprise-tier з no-train (Claude for Work, Copilot Business, Azure OpenAI) | Перевірити DPA та data-residency |
| 🔴 | **Не давати моделям.** Лише локальні інструменти або маскувати до 🟡/🟢 | Секрети — vault/env; PII — pseudonymize |

## 5. Швидка довідка: що шукати в тексті

```
grep -iE для автоматичного виявлення:
  Секрети:    (api[_-]?key|token|password|secret|conn.*string|postgres://|mysql://)
  PII:        (\b\d{10}\b|\+380|\b[A-Z]{2}\d{2}\b.*\d{4,}|@.*\.(com|test|ua))
  Картки:     (\b\d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}\b)
  IBAN:       (\b[A-Z]{2}\d{2}\s?\d{4}\s?\d{4}.*\d{3,}\b)
```

## 6. Якщо стався витік

- [ ] Ротувати скомпрометовані секрети **негайно** (< 15 хв).
- [ ] Нотифікувати відповідального (security team / tech lead).
- [ ] Перевірити audit-лог: хто і коли мав доступ.
- [ ] Зафіксувати інцидент у внутрішній системі.
- [ ] Оновити цей чек-ліст якщо з'явився новий патерн витоку.
