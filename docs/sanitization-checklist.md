# Чек-ліст санітизації даних для AI (команда: WS2 homework)

## 1. Класифікуй (світлофор)

- [x] **🔴 Ніколи публічним:** секрети (API keys, tokens, паролі, connection strings), PII (ім'я, email, телефон, дата народження, паспорт, ІПН), банківська таємниця (картка, CVV, IBAN, баланс), production-логи/дампи, внутрішні дані з реальних систем.
- [x] **🟡 Лише enterprise/no-train:** внутрішня логіка, назви компонентів/гілок, бізнес-правила, анонімізовані логи, тикети з контекстом, код під NDA.
- [x] **🟢 Можна публічним:** загальний опис задачі, синтетичні приклади, OSS-код, документація без даних, технічні питання без реальних значень.
- [x] Сумнів → вважати 🔴.

## 2. Що шукати

- [x] Імена, email, телефони, дати народження, паспортні дані, ІПН.
- [x] Картки, CVV, IBAN, рахунки, баланси.
- [x] Secrets у URL, headers, env, logs, code snippets.
- [x] Connection strings, tokens, API keys, passwords.
- [x] Реальні ідентифікатори транзакцій, логи з production, stack traces із значеннями.

## 3. Маскування й санітизація

- [x] **Redaction** — прибрати повністю (`[REDACTED]`): те, що не потрібно для задачі.
- [x] **Masking** — зберегти формат, прибрати значення (`****-1234`, `<IBAN>`): коли моделі потрібна структура.
- [x] **Synthetic** — підмінити реалістичним вигаданим значенням: коли потрібні дані для відтворення, але без реального контексту.
- [x] **Secrets — out-of-band:** не маскувати, а не давати моделі взагалі; якщо секрет вже потрапив у контекст, вийняти його з діалогу й ротувати.

| Дата народження | 14.03.1987 | `[DOB_1]` |

| Картка | 4111 1111 1111 1234 | `****-1234` |
| IBAN | UA90 3052 ... 3456 789 | `<IBAN>` |
| Secrets / API keys | sk-live-... / postgres://... | `<SECRET_OUT_OF_BAND>` |

## 5. Інструмент / tier під категорію

| Категорія | Рекомендований інструмент / tier | Нотатки |
|---|---|---|
| 🟢 | Будь-який загальний інструмент / public-safe | Можна використовувати для загальних описів і синтетики |
| 🟡 | Enterprise / no-train | Потрібен контроль доступу, відсутність навчання на даних |
| 🔴 | Не давати моделям; лише локально / маскувати | Секрети не повинні потрапляти в контекст |

## 6. Чому для 🟡 даних потрібен enterprise/no-train

Для 🟡 даних, навіть якщо вони не містять секретів, важливо обмежити використання AI середовищем з enterprise governance: доступом за ролями, відсутністю навчання на введених даних, контрольованою резидентністю та журналюванням. Це дозволяє зберегти внутрішню логіку, назви систем і бізнес-правила поза публічним контекстом, не ризикувати витоком або несанкціонованим використанням.
