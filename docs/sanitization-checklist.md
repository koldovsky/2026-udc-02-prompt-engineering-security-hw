# Чек-ліст санітизації даних для AI (команда: UDC WS2)

> Це багаторазовий документ для команди. Мета — зберегти корисний контекст для AI, не розкриваючи чутливі дані.

## 1. Класифікуй (світлофор)

- [x] **🔴 Ніколи публічним:** секрети (ключі, токени, паролі, connection strings),
      PII (ім'я, email, телефон, ДН, паспорт, ІПН), банківська таємниця
      (картка, CVV, IBAN, рахунок, баланс), production-дані/дампи,
      медичні/державні/регульовані дані.
- [x] **🟡 Лише enterprise/no-train:** внутрішній код під NDA, бізнес-логіка,
      схеми БД, архітектура, тікети з контекстом, анонімізовані логи,
      назви компонентів/гілок.
- [x] **🟢 Можна публічним:** публічний/OSS-код, синтетика, загальні питання,
      документація без даних, стек-трейс без значень.
- [x] Сумнів → вважати 🔴.

## 2. Очисти (техніка під категорію)

- [x] **Redaction** — прибрати повністю (`[REDACTED]`): те, що не потрібно задачі.
- [x] **Masking** — зберегти формат, прибрати значення (`****-1234`, `<IBAN>`):
      коли моделі потрібна структура.
- [x] **Synthetic** — підмінити реалістичним вигаданим: коли потрібні «справжні
      на вигляд» дані для відтворення.
- [x] **Секрети — out-of-band:** не маскувати, а **не давати взагалі**
      (env / secret store / vault); якщо «світилися» — ротувати.

## 3. Що шукати перед відправкою в AI

- [x] Імена, email, телефони, ДН, паспорт, ІПН, адреси.
- [x] Ключі, токени, паролі, connection strings, URL з credentials.
- [x] Банківські дані: картка, CVV, IBAN, баланс, рахунки.
- [x] Production логи, дампи, stack traces з реальними значеннями.
- [x] Внутрішні назви компонентів, гілок, репозиторіїв, endpoint-ів без потреби.
- [x] Скріншоти, прикріплені файли, dump-дані, JSON з реальними значеннями.

## 4. Перевір перед відправкою

- [x] Чи можна реідентифікувати людину з решти полів? (ім'я + ДН + місто + посада)
- [x] Чи не несе чутливе вставлений URL / скріншот / лог?
- [x] Чи збережена **задача** після санітизації?
- [x] Чи відповідає інструмент/tier категорії даних? (no-train для 🟡)
- [x] Чи не залишилися «підказки» у тексті, які можуть вплинути на модель?

## 5. Інструмент під категорію

| Категорія | Дозволений інструмент / tier | Нотатки |
|---|---|---|
| 🟢 | Будь-який загальний інструмент / public-OSS | Можна надсилати без обмежень, якщо дані не містять PII/секретів |
| 🟡 | Copilot Business / Claude for Work — no-train | Лише з enterprise-конфігурацією, без навчання на даних |
| 🔴 | Не давати моделям; лише локально/маскувати | Секрети — не в документ, не в prompt, а зберігати у vault/secret store |

## 6. Короткий вибір інструменту для 🟡-даних

- [x] Для 🟡-даних я б обрав enterprise-tier інструмент з режимом no-train.
- [x] Причина: це дає контроль доступу, зменшує ризик навчання моделі на внутрішньому контексті й краще відповідає вимогам data residency / корпоративної політики.
- [x] Якщо дані можуть містити конфіденційний контекст або не підходять для зовнішнього оброблення, їх варто ще раз мінімізувати або замінити синтетикою.

## 7. Практичний шаблон маскування

- [x] Картка → `****-1234`
- [x] IBAN → `<IBAN>`
- [x] Ім'я → `[CUSTOMER_1]`
- [x] Email → `[REDACTED_EMAIL]`
- [x] Телефон → `[REDACTED_PHONE]`
- [x] Секрети → `<SECRET_OUT_OF_BAND>` і не виносити в документ / prompt

## 7. Якщо стався витік

- [x] Ротувати скомпрометовані секрети негайно.
- [x] Нотифікувати відповідального (security/lead).
- [x] Зафіксувати інцидент і оновити цей чек-ліст.
