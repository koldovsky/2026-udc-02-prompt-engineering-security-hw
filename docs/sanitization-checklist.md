# Чек-ліст санітизації даних для AI (команда: UDC / prompt-engineering)

> Багаторазовий документ для підготовки тікетів, логів і CRM-витягів перед
> відправкою в AI-інструменти. Оновлюйте після інцидентів і змін політики.

## 1. Класифікуй (світлофор)

- [ ] **🔴 Ніколи публічним:** секрети (API keys, токени, паролі, `postgres://…`,
      `X-API-Key`, JWT), PII (ПІБ, email, телефон, ДН, паспорт, ІПН/РНОКПП),
      банківська таємниця (PAN, CVV, exp, IBAN, баланс, повні реквізити),
      production-логи/дампи з ідентифікаторами, медичні/держ./регульовані дані.
- [ ] **🟡 Лише enterprise/no-train:** внутрішні компоненти (`payments-core`),
      імена класів/методів, гілки (`feat/…`), архітектура, схеми БД, тікети з
      технічним контекстом, частково анонімізовані логи.
- [ ] **🟢 Можна публічним:** загальний опис бага, acceptance criteria без даних,
      синтетичні приклади, публічний/OSS-код, стек без значень полів.
- [ ] **Сумнів → вважати 🔴.**

### Швидкі патерни пошуку

| Патерн | Категорія |
|--------|-----------|
| `\d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}` | 🔴 PAN |
| `UA\d{2}\s?\d{4}…` | 🔴 IBAN |
| `sk-live-`, `sk-`, `Bearer `, `X-API-Key` | 🔴 секрет |
| `postgres://`, `mysql://`, `:password@` | 🔴 connection string |
| `@gmail.`, `+380`, `\d{10}` (ІПН) | 🔴 PII |
| `FeeCalculator`, `feat/`, internal hostnames | 🟡 |

## 2. Очисти (техніка під категорію)

| Техніка | Коли | Приклад |
|---------|------|---------|
| **Redaction** | Поле не потрібне для задачі | `ДН: [DOB_REDACTED]` |
| **Masking** | Потрібна структура, не значення | `****-1234`, `<IBAN>`, `+380 ** *** ** 67` |
| **Synthetic** | Потрібен «живий» контекст без реальних людей | `[CUSTOMER_1]`, `user_42@example.test` |
| **Out-of-band** | Секрети — **ніколи** в промпт/документ | env, Vault, 1Password; у тексті лише `<SECRET_OUT_OF_BAND>` |

- [ ] **Redaction** — прибрати повністю те, що не потрібне моделі.
- [ ] **Masking** — зберегти формат для відтворення бага без реальних значень.
- [ ] **Synthetic** — підмінити вигаданими, але консистентними placeholders.
- [ ] **Секрети — out-of-band:** не маскувати частково — **не давати взагалі**;
      якщо витік у лог — **ротувати** ключ/пароль.

## 3. Перевір перед відправкою

- [ ] Чи можна **реідентифікувати** людину з комбінації полів? (ім'я + ДН + місто)
- [ ] Чи немає чутливого у **URL, скріншоті, вкладенні, логу**?
- [ ] Чи **збережена задача** — модель розуміє баг без оригінальних значень?
- [ ] Чи **інструмент/tier** відповідає найвищій категорії в контексті?
- [ ] Чи немає **копіпасту** оригіналу поруч із санітизованою версією в тому ж чаті?

## 4. Інструмент під категорію

| Категорія | Дозволений інструмент / tier | Нотатки |
|-----------|------------------------------|---------|
| 🟢 | Cursor / ChatGPT / Copilot (standard), локальні моделі | Загальні питання, OSS, синтетика |
| 🟡 | **Cursor Privacy Mode** / **Copilot Business** / **Claude for Work** з **no-train** і **enterprise** угодою | Внутрішня логіка, імена компонентів, гілки — лише коли є DPA і заборона тренування |
| 🔴 | **Не давати моделям** — лише локальна санітизація, потім 🟢-контекст | PII, секрети, банківські дані, prod-дампи |

### Вибір tier для 🟡 — рішення команди (Task B, п. 4)

**Первинний вибір:** **Cursor з Privacy Mode** (або **GitHub Copilot Business** /
**Claude for Work** за аналогічною enterprise-угодою).

| Вимога | Як закриваємо |
|--------|----------------|
| **no-train** | Privacy Mode / Business tier — постачальник не використовує промпти для навчання базових моделей. |
| **enterprise** | Організаційна ліцензія + DPA; аудит доступу; окремі політики для фінтех-команд. |
| **data residency** | Обробка в ЄС (або регіон з політики); не надсилати 🟡 у US-only consumer tier без угоди. |

**Коли 🟡 лишається в контексті** (як у `materials/sensitive-ticket.md`: імена класів,
гілки, компоненти) — лише через інструмент з трьома гарантіями вище.

**Коли enterprise недоступний** — не ескалувати ризик: санітизувати до 🟢
(див. [`sanitized-ticket.md`](./sanitized-ticket.md)) і працювати в стандартному tier.

**Не використовувати для 🟡:** ChatGPT Free, Copilot Individual, публічні API без DPA.

## 5. Якщо стався витік

- [ ] Ротувати скомпрометовані секрети **негайно** (API keys, DB passwords).
- [ ] Нотифікувати security lead / відповідального за дані.
- [ ] Зафіксувати інцидент (що, коли, який інструмент) і оновити цей чек-ліст.
- [ ] Переглянути, чи не залишився оригінал у історії чату / PR / логах CI.
