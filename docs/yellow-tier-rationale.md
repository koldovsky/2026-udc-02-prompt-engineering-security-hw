# Вибір інструменту/tier для 🟡-даних

## Рішення

**Enterprise-tier з no-train** (Claude for Work, Copilot Business, Azure OpenAI).

## Три обов'язкові критерії

| Критерій | Що гарантує | Чому важливо |
|----------|-------------|--------------|
| **No-train** | Дані не використовуються для навчання моделі | Внутрішня логіка, назви компонентів, схеми БД не потраплять у відповіді іншим користувачам |
| **DPA** (Data Processing Agreement) | Юридична відповідальність провайдера | ToS — лише обіцянка, яку можуть змінити; DPA — зобов'язання з наслідками |
| **Data residency** | Обробка в потрібній юрисдикції (EU/UA) | Регуляторна вимога для метаданих клієнтів, навіть без прямих ідентифікаторів |

## Чому не публічний tier

- 🟡-дані — це NDA-матеріал (код, архітектура, тікети з контекстом).
- Публічний API без no-train = потенційний витік через training pipeline.
- Ймовірність мала, але ризик непропорційний вартості enterprise-підписки.

## Чому не локальна модель

- Прийнятна альтернатива, але якість відповідей нижча.
- Підходить як fallback якщо enterprise-tier недоступний.
- Потребує власної інфраструктури та підтримки.
