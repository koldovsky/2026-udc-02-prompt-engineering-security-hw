# Context layer (Task D)

## Що покращив (один шар)

- [x] ignore-файл (`.cursorignore`) — додав 3 нові патерни поверх наявних:
  - `repomix-output.*` — згенеровані дампи контексту (шум, ніколи не потрібні).
  - `coverage/` — звіти покриття (генеровані, великі, низький сигнал).
  - `*.pem` — приватні ключі (ніколи не давати агенту).
- Наявні патерни вже прибирали `node_modules/`, lockfiles, білди, `.env`/`.env.*`.
- [x] **Claude Code native-шар** (`.claude/settings.json`) — оскільки в Claude
  Code немає `.cursorignore`, додав `permissions.deny` із правилами `Read(...)`
  на `.env`, `.env.*`, `*.pem`, `*.key`. Це **жорсткіше** за ignore: Cursor лише
  ховає файл, а Claude Code блокує сам інструмент читання.
- **Чому саме ці шари:** ignore-файл б'є одразу по двох цілях — прибирає
  найбільше джерело шуму (`node_modules`) і прибирає чутливе (`.env`, `*.pem`)
  з контексту. `permissions.deny` додає твердий шар безпеки під сам інструмент
  (синергія з Task C: навіть успішний injection не прочитає `.env`).

> Відповідність інструментів: `.cursorignore` → Cursor; `.gitignore` +
> `.claude/settings.json` (`permissions.deny`) → Claude Code; `AGENTS.md` /
> `CLAUDE.md` → правила поведінки для обох.

## Висновок

Курація контексту через ignore-файл прибрала ~99.8% токенів (майже все —
`node_modules` і lockfiles), які не несуть жодного сигналу для міркування про
`app/`. Це напряму менші витрати й менше «шуму», через який агент розповзається.
Бонусом той самий шар **виключив чутливе** (`.env`, синтетичний тікет) з
контексту — тобто курація працює і як шар безпеки, не лише вартості.
