# A/B промптів (Task E, bonus)

**Задача (на `app/`):** додати валідацію `percent` у `applyDiscount`
(зараз приймає будь-яке число, напр. 150 чи -10, і мовчки рахує неправильно).

> Обидва прогони виконані реально на `app/src/money.ts` з `npm test`, після чого
> код повернуто в початковий стан (посаджений баг лишається для перевіряючих).
> Це навчальний експеримент, не фікс у PR.

## Промпт A — базовий

```
додай валідацію в applyDiscount
```

## Промпт B — структурований

```markdown
Role: Senior TS engineer (Node 22, vitest) у цьому репо. Працюєш test-first.
Goal: Валідувати вхід applyDiscount у app/src/money.ts.
Context: Інтегер-центи. Зараз percent не перевіряється; валідний шлях
  (0..100) має лишитись без змін. Перевірка: `cd app && npm test`.
Constraints:
- Кидати Error на percent поза 0..100 і на нечислові значення.
- Не міняти поведінку для валідних входів; публічний підпис лишити сумісним.
- Без нових залежностей; без секретів/PII.
Acceptance criteria:
- applyDiscount(_, 150) і applyDiscount(_, -10) кидають помилку.
- Додано тест на межі; усі тести зелені.
Output: diff money.ts + новий тест + 1 рядок пояснення.
```

## Порівняння

| Критерій | Промпт A | Промпт B |
|---|---|---|
| Ітерацій до прийняття | ~3 (фікс → попросити верхню межу → попросити тест) | **1** |
| Тестів після прогону | 4 (нових 0) | **5 (новий 1)** |
| Output (рядків коду) | ~1 (`if (percent < 0) percent = 0;`) | ~4 коду + 4 тесту |
| Output токени (≈) | ~40 (короткий, але неповний) | ~180 (довший, але повний) |
| Якість результату | мовчазний clamp; **верхня межа 100 не перевірена**; 150% усе ще ламає | кидає Error на 0..100 і нечислові; поведінка валідного шляху незмінна |
| Правки безпеки/валідації | довелось би просити окремо (afterthought) | **враховано одразу** (межі + тест) |

## Висновок

Структурований промпт окупив «зайвий» текст: результат прийнято **за 1 ітерацію**
замість ~3, безпеку (межі + помилку) враховано одразу, і додався регресійний
тест. Базовий промпт дав коротшу відповідь, але неповну й мовчазну — верхня межа
лишилась дірою, тестів нема, тож реальна вартість (час + токени на дораунди)
вища. Найбільша різниця — саме в **правках безпеки/валідації**: структура змушує
агента подумати про межі ДО написання коду, а не після ревʼю.
